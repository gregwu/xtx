# V0.2: 5-minute research + prior-day state

V0.2 makes the first Mini-XTX pipeline materially more realistic before adding a larger deep model.

## What changed

### 1. Executable targets

The original research return is still available:

```
ret_fwd_H = close[t+H] / close[t] - 1
```

V0.2 also builds a next-bar executable return:

```
ret_exec_fwd_H = close[t+H] / open[t+1] - 1
```

This avoids crediting a strategy with execution at the same close used to form the signal.

### 2. MFE / MAE targets

For each horizon, the dataset now contains:

- `mfe_fwd_H`: maximum favorable excursion from next-bar open
- `mae_fwd_H`: maximum adverse excursion from next-bar open
- volatility-normalized `target_mfe_H` and `target_mae_H`

LightGBM trains auxiliary models and writes:

- `pred_H`
- `pred_mfe_H`
- `pred_mae_H`

These can later be combined into a risk-adjusted opportunity score.

### 3. Daily + 5m fusion without current-day leakage

Pass daily bars while building the 5m dataset:

```bash
python -m mini_xtx.cli build \
  --input /data/us_5m \
  --daily-input /data/us_daily \
  --output /data/features_5m_v02.parquet \
  --freq 5m
```

Daily features are shifted by one session per symbol before joining to intraday rows. A 5m row on session D therefore sees daily state from D-1 or earlier, never D's completed daily bar.

The joined columns use the `daily_` prefix and are automatically picked up by LightGBM.

### 4. Purged split boundaries

Training and validation tails are purged by the maximum target horizon by default. For the 5m setup this is 12 bars.

Override if needed:

```bash
python -m mini_xtx.cli train-lgbm \
  --data /data/features_5m_v02.parquet \
  --outdir artifacts/lgbm_5m_v02 \
  --train-end 2024-12-31 \
  --valid-start 2025-01-01 \
  --valid-end 2025-12-31 \
  --test-start 2026-01-01 \
  --purge-bars 12
```

This prevents a target at the end of train/validation from reaching across the next split boundary.

### 5. Non-overlapping evaluation by default

The ranked backtest now samples one rebalance every H bars for an H-bar target and uses the next-open executable return when available:

```bash
python -m mini_xtx.cli backtest \
  --predictions artifacts/lgbm_5m_v02/predictions.parquet \
  --horizon ret_fwd_6 \
  --top-frac 0.02 \
  --cost-bps 2
```

For `ret_fwd_6`, the default rebalance stride is six bars. Use `--stride 1` only when intentionally studying overlapping signal behavior.

The report now separates long and short returns and computes cross-sectional IC on the full universe rather than only the selected tails.

## First experiment to run

Use exactly the same universe and time split for all four intraday horizons:

| horizon | bars | clock time |
|---|---:|---:|
| h1 | 1 | 5m |
| h3 | 3 | 15m |
| h6 | 6 | 30m |
| h12 | 12 | 60m |

Record for return, MFE, and MAE models:

- validation IC
- test IC
- best iteration
- long-tail return
- short-tail return
- net top/bottom portfolio return after cost

The first decision is not "which model is most accurate?" It is whether the cross-sectional IC curve is stable out of sample and whether the extreme ranks survive executable-entry assumptions and costs.

## Recommended next step after this branch

Do not enlarge the Transformer until the 5m LightGBM benchmark is established. If the 30m/60m models show repeatable IC, the next model should use a shared temporal representation with daily state and auxiliary return/MFE/MAE heads. Cross-asset attention should follow only after that baseline is reproducible.
